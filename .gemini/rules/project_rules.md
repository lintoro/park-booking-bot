# 專案專屬規範 (Amusement Park Group Booking LINE Bot Project Rules)

1. **語言原則**：所有互動、說明、文件、Commit 與程式碼註解必須 100% 使用「繁體中文（台灣）」，嚴禁簡體中文。
2. **資安與參考資料隔離**：
   - 本地 `/參考資料勿上傳/` 資料夾嚴禁納入 Git 追蹤與推送，嚴防企劃與業務資訊外洩。
   - 所有 LINE Messaging API 金鑰與 Google 憑證均透過 `.env` 與金鑰檔外部注入，嚴禁硬編碼。
   - 伺服器端必須嚴格驗證 LINE `X-Line-Signature` 簽章。
3. **園區營運防呆鐵律 (Business Guardrails)**：
   - **成團門檻**：最少 20 人，未滿 20 人自動導向散客通路。
   - **容量限制**：每日總量 1,000 人（上午場 400 人 / 下午場 600 人）。
   - **營業時間與截止**：平日 10:00~18:00、假日 10:00~19:00；**17:00 以後一律不開放團體預約入場**。
   - **當日急單防呆**：上午送單限預約下午場（$\ge$ 13:00）；下午送單限預約 15:00 以後。
   - **免票優惠計算**：每 1 台遊覽車享 1 司機 + 1 領隊免票（共 2 位免票，不計入金額）。
   - **訂金政策**：門票總額之 10% 彈性訂金。
4. **對話狀態與人機協同 (Conversational State & Human Handoff)**：
   - **15 分鐘逾時防護**：客戶中斷對話超過 15 分鐘未回應自動重置狀態，避免卡關。
   - **真人接手開關**：偵測「專人」、「客服」、「業務」、「電話」、「人工」等關鍵字立即暫停機器人並發送聯絡名片。
5. **解耦設計 (Architecture Decoupling)**：
   - LINE Flex Message 採用獨立 JSON 模板管理，與後端語言解耦，確保未來低成本平移至 Node.js。
   - 業務驗證邏輯與 Webhook 路由分離。
6. **四大維護日誌規範**：
   - 歷次重大變更必須同步維護 `docs/PROJECT_CONVERSATION_HISTORY.md`、`PROGRESS.md`、`ISSUES_LOG.md` 與 `PROJECT_HANDOVER.md`。
